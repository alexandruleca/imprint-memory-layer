# Native installers

Windows x64 uses Inno Setup; macOS Intel/ARM use pkgbuild/productbuild. Both consume a validated staged release tree from `make package` or `make package-local`. See [building](../docs/building.md), [platform validation](../docs/platform-validation.md) and [ADR 0002](../docs/adr/0002-build-and-validate-before-publication.md).

Windows installs per user under `%LOCALAPPDATA%\Programs\Imprint`. Its wizard runs the bundled uv/bootstrap path and client registration, displaying the log. The final `.setup-result` reports completion; `.first-run.done` alone does not. Silent installs run the setup script explicitly. The wizard's profile page pre-selects GPU, which keeps llama.cpp's GPU build only when it finds a GPU; a fresh silent install uses `cpu`. The Repair shortcut reuses saved profile choices and shows setup's output in its console window. Uninstall stops Imprint's processes and removes everything, data included, unless you choose to keep the data (`/KEEPDATA` when silent); see [ADR 0028](../docs/adr/0028-complete-uninstall.md).

macOS installs `/Applications/Imprint.app` and a `/usr/local/bin/imprint` link. Root postinstall only fixes permissions/quarantine and the CLI link. First launch provisions Python/dependencies in the user's writable `~/.local/share/imprint` through the native Swift progress helper, with a Terminal fallback, on the `auto` profile without asking. It builds llama.cpp from source, which needs the Xcode Command Line Tools, until prebuilt Metal wheels from this repository's release workflow are pinned (planned). When setup succeeds, either path continues with `imprint ui open`, so Imprint opens without a second launch; the progress window stays open with Close only when setup or opening fails. It does not install Python as root. Source resources remain inside the app bundle.

These installers bundle the CLI, source, static dashboard, Electron shell and uv, but download managed Python, wheels, Qdrant and models as needed. They require a network on first use. Signing/notarization, fully offline payloads and interactive GUI validation are still outstanding; do not treat the local Linux checks as macOS/Windows execution evidence.

Build the shell and dashboard first, then the platform archive, then `make installer-macos ARCH=arm64` on macOS or `make installer-windows` with Inno Setup on Windows. The shared release workflow performs this ordering and includes every deliverable in `SHA256SUMS` before publication.

After setup, the Windows shortcut launches the bundled GUI directly. On every desktop target, the shell displays its splash before starting a hidden API, retains startup logs and offers retry on failure. Closing the dashboard keeps the service running; **Quit Imprint** in the sidebar/tray stops the API owned by that app. A reused explicit CLI daemon and shared Qdrant remain independent. macOS receives the writable user venv path from the CLI. See [ADR 0025](../docs/adr/0025-desktop-owned-background-service.md).

The Windows wizard's WSL page opts selected detected Claude Code/Codex profiles into a shared Windows runtime through stdio; it does not install a Linux runtime. `.wsl-integrations.txt` persists explicit choices for repair/silent upgrades and is excluded from release archives. Fresh silent installs skip WSL registration. `imprint wsl setup/remove` supports manual custom users/profiles. Disconnect Linux profiles before uninstalling the Windows runtime; uninstall preserves Linux settings. See [ADR 0026](../docs/adr/0026-windows-installer-wsl-client-bridge.md).
