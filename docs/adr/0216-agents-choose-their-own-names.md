## Context

On 2026-11-27, while the Board was being designed, the owner asked: "let's also make imprint make agents choose they're own names would be nice".

- The Agents page names a session by its client, version and directory ([ADR 0117](0117-the-dashboard-shows-each-agent-session-and-its-calls.md)). Two Claude Code sessions in one folder look alike there.
- On the Board, several agents claim, checkpoint and comment on the same Tasks, and comments can be addressed to one of them ([ADR 0212](0212-agents-talk-through-comments-on-tasks.md)). A client name does not tell two sessions of one client apart, and a random id is not something a person or an agent remembers.

## Decision

**Choosing.** An agent session chooses a name with `task_edit` (action `name`) before it first claims or comments on a Task. The built-in `imprint-tasks` skill and the context Imprint gives at session start ask it to. An agent that claims or comments without having chosen gets a fallback of its client and four characters (`codex-k3fz`), which it can replace.

**Form and uniqueness.** A name is 2 to 24 letters, digits and hyphens, shown as chosen and compared without case. It is unique among the agent sessions of the workspace that are live on this device or hold a claim seen from another device; a taken name is refused with a free one suggested. Where two devices chose the same name before they synced, the Board shows each with its device (`grimforge · bedrock`).

**Keeping it.** The name belongs to the agent session ([ADR 0210](0210-claims-are-leases-held-by-the-agent-session.md)), so a resumed conversation, or a restarted server that presents its claim token, keeps it. Every event the session writes records its name at that moment, so the history reads the same after a rename.

**Where it shows.** On the Board (holders, checkpoints, comments), on the Agents page next to the client and directory, and in handoffs. A comment addressed to `@grimforge` reaches that session. The user can rename an agent from the dashboard.

## Rejected alternatives

- **Names generated by Imprint only.** Kept as the fallback; the owner asked that agents choose.
- **Requiring a name before any Imprint call.** A session that only searches memory has no reason to name itself, and every client would need to be told before its first call.

## Consequences

- People and agents can tell sessions apart and address one of them.
- A name chosen by the model can be silly or repeated across sessions; uniqueness is enforced only among live sessions, so a name can return later for another session.
- Agent sessions gain a name field that the Agents page and the Board show.

## Invalidation conditions

- If agents rarely choose a name (most claims on the owner's Boards are by fallback names), have Imprint choose a memorable name instead of asking.
- If names collide across devices often enough to confuse addressing, make them unique across synced devices through a claim on the name.

## Validation

Proposed: nothing is implemented and nothing was executed.
