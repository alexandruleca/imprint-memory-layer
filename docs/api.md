Experimental voice routes are documented in [Echo voice companion](live-voice.md):
`GET /api/voice/status`, `POST /api/voice/sessions` and `WS /api/voice/stream`.
Voice requires exact same-origin loopback access and a one-use session capability;
the native speech listener is private to the API.

The Imprint container runs a FastAPI server on port **8420**. Everything the
built-in dashboard does — search, ingest, retag, graph walks, sync, chat — is
available over local HTTP for clients on the same machine: a backend service pushing
data, a CI job retagging after a merge, your own UI, or a quick `curl` to see
what's in memory.

:::note
The dashboard API supports loopback access. It validates the connection address, Host and browser Origin; there is no authenticated remote dashboard mode. The WIP `/api/browser/*` router additionally admits an explicitly paired Chrome extension with workspace-bound credentials; it does not change general dashboard access. The supported launcher disables proxy-header interpretation. Container mode explicitly permits NAT peers and relies on host ports published on `127.0.0.1` plus a trusted container network. Host/Origin headers can be forged by a remote HTTP client, so they do not replace network isolation. TLS alone does not add authentication.
:::

### Quick tour

```bash
# 1. Confirm the server is up
curl -s http://localhost:8420/api/version

# 2. Search the corpus
curl -s "http://localhost:8420/api/search?q=chunking+system&limit=5"

# 3. Enqueue an ingest job — returns {job_id, position}
curl -s -X POST http://localhost:8420/api/commands/ingest \
  -H "Content-Type: application/json" \
  -d '{"args": ["/workspace"], "project": "my-project"}'

# 4. Tail job output live (Server-Sent Events)
curl -N http://localhost:8420/api/jobs/<job_id>/stream
```

In Docker, publish `127.0.0.1:8420:8420` and use the same local URL. Arbitrary remote Host/Origin values are rejected.

## Endpoint reference

Endpoints are grouped by responsibility. The Postman collection mirrors this
structure folder-for-folder so you can scan the reference and the collection
side by side.

### Overview & stats

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/version` | Version of this installation's imprint CLI (`bin/imprint` beside the package, else PATH); `unknown` when it can't be run. |
| GET | `/api/update` | Latest release, `update_available`, how this installation updates (`method`, or `unsupported` with the reason), plus `running`, `failed` (the updater exited with an error; a successful exit hands over to the installer or the server restart) and the updater `log` tail. The release check is cached for six hours; `?refresh=true` repeats it. |
| POST | `/api/update` | Start `imprint update -y` detached; it restarts this server once the release is installed. 400 when this installation cannot update or is current, 409 while an update or job is running. |
| POST | `/api/restart` | Finish in-flight requests and exit with status 75; the desktop app or `imprint ui` that started the server starts it again with the installed code (`imprint ui restart` uses this, [ADR 0050](./adr/0050-registered-dashboard-server-and-supervised-restart.md)). 409 when the app is not served by Imprint's launcher. |
| GET | `/api/stats` | Aggregate counts per project, type, and language. |
| GET | `/api/overview` | Bubble-chart overview. Repeat `?type=` for multi-filter. |
| GET | `/api/timeline` | Recent activity feed. `?project=`, `?limit=`. |
| GET | `/api/cross-project` | Project-to-project similarity matrix. |

### CLI commands (async jobs)

Every queue-safe imprint CLI command is reachable here. The endpoint enqueues
a background job, returns `{job_id, position}` immediately, and the job runs
through the same single-slot queue the dashboard uses.

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/commands/{command}` | Enqueue a command. See below for the allowlist. |
| GET | `/api/queue` | Active + queued + recent jobs. |
| GET | `/api/jobs/{id}` | Job status + exit code. |
| GET | `/api/jobs/{id}/stream` | SSE stream of live stdout/stderr. |
| POST | `/api/jobs/{id}/cancel` | SIGTERM the job (SIGKILL after 3 s). |

**Allowlisted commands:** `status`, `ingest`, `ingest-url`, `refresh`,
`refresh-urls`, `retag`, `learn`, `config`, `wipe`, `sync`, `migrate`,
`workspace`.

`migrate` takes `from`, `to`, one of `project` / `topic` / `source`, and the
booleans `copy` (keep the source's memories; `--copy`) and `dry_run`.

`ingest` and `refresh` take the path as `dir`. A `dir` the workspace's approved
roots would refuse is rejected before anything is queued, with 409
`{"error", "code": "root_not_approved", "workspace", "root", "overlaps"}`:
`root` is the directory to approve (the path, or a file's folder) and
`overlaps` lists other workspaces whose roots it shares. A workspace without
roots binds its first ingest as usual. The dashboard offers to add `root`
through `POST /api/workspace/roots` (confirming any sharing) and submits the
job again. CLI argv sent as `args` is checked when the job runs, like a direct
CLI call. See [workspaces](workspaces.md#approved-roots-and-sharing).

```bash
# Ingest a URL in the "docs" project
curl -s -X POST http://localhost:8420/api/commands/ingest-url \
  -H "Content-Type: application/json" \
  -d '{"args": ["https://example.com/article"], "project": "docs"}'
```

:::tip
For inline content that doesn't live at a URL or filesystem path (API uploads,
pasted transcripts, generated logs), prefer the **`ingest_content` MCP tool**
over `/api/commands/ingest-url` — it takes the bytes inline, handles
dedup/replace by `name`, and avoids a trip through the job queue. See
[MCP tools](./mcp.md#writes).
:::

### Sync

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/sync/export` | Write a snapshot bundle to a server-side path. |
| POST | `/api/sync/import` | Restore from a server-side bundle path. |
| GET | `/api/sync/export/download` | Stream a zipped snapshot to the browser. |
| POST | `/api/sync/import/upload` | Multipart upload of a zip bundle. |
| POST | `/api/sync/serve` | SSE stream: serve one workspace for live sync. JSON body (all optional): `workspace` (an existing workspace; default: active, captured at start), `direction` = `both` \| `send` \| `receive` (default `both`) and `relay` (host, default: the public relay). Invalid values return 400. A POST with a JSON body so a cross-site page cannot start a session. |
| POST | `/api/sync/receive` | SSE stream: join a served room. Body: `{"code"}` — the share code the serving side shows, `<room>-<pin>`, on its own or behind `<host>/` or `wss://<host>/` — plus optional `workspace` (default: active; a new name is created when data arrives) and `direction` = `receive` (default) \| `both` \| `send`. A send-only receive needs an existing workspace. |
| POST | `/api/sync/cancel` | Cancel an active peer-sync session by `session_id`. |
| POST | `/api/sync/approve` | Resolve a pending sync decision. Body: `{"session_id": "...", "decision": "accept" \| "trust" \| "reject"}`. Serving: answers `approval_required` (`trust` also remembers the device). Joining: answers `confirm_push` (`accept` sends the workspace, anything else skips the push). |
| GET | `/api/desktop-learn/history` | Previously-indexed Claude Desktop / ChatGPT Desktop export zips (SHA-keyed). |
| POST | `/api/desktop-learn/scan` | One-shot Downloads scan for new desktop-app conversation exports. Body (optional): `{"paths": ["/extra/dir", ...]}`; extra folders must be inside the workspace's approved roots (ADR 0034). Returns the structured scan result used by the dashboard. |

Live peer sync runs the same sessions as `imprint sync` (one implementation,
`imprint/sync_ws.py`), end-to-end encrypted — see [sync](./sync.md). Beyond
status events, `serve` emits `room` (`code`, `target` — what the other
machine enters: the code, behind the relay address unless it is the default —
`room_id`, `pin`, `relay`, `workspace` and the `pull`/`push` grant peers
receive), `approval_required` / `auto_accepted` / `trusted`, `peer_connected`
and `refused` (`request`: `pull` \| `push`) when its direction policy turns a
peer's request down; `receive` emits `session` (`session_id`, `workspace`),
`peer_connected` (the serving device), `confirm_push` (`workspace` and the
serving device; answer through `/api/sync/approve`), `plan` (`pull`, `push`,
`skipped` reasons), `workspace_created` and `warning`. `progress` events carry
`phase` = `send` \| `receive` \| `pull` \| `push` \| `store`. The session uses
the workspace passed explicitly and never changes the active one. Snapshot
endpoints cover export → transfer zip → import when a relay connection isn't
available.

### Chat

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/chat/status` | Configured provider + model + readiness. |
| GET | `/api/chat/sessions` | List chat sessions. |
| POST | `/api/chat/sessions` | Create a new session. |
| GET | `/api/chat/sessions/{sid}` | Session transcript. |
| POST | `/api/chat/sessions/{sid}/rename` | Rename session. |
| DELETE | `/api/chat/sessions/{sid}` | Delete session. |
| POST | `/api/chat` | Send a message. Returns an SSE stream of tokens + tool calls. |

`/api/chat` events, in order of appearance:

- `install_start`, `install_progress` (`line`), `install_complete`: the first
  local chat installs the llama.cpp binding (`imprint profile add-llm`).
- `download_start` (`file`, `repo`, `path`), `download_progress`
  (`downloaded`, `total` bytes), `download_complete`: the model download.
- `load_start`: the local model is being loaded into memory.
- `token` (`text`): reply text. Tool-call markup is never streamed, so the
  tokens of a reply concatenate to what the user sees.
- `tool_call` (`name`, `args`), `tool_result` (`name`, `result`).
- `assistant_message` (`text`): the complete reply, stored in the session.
- `error` (`error`), then `done`.

Closing the stream early stops the reply; the text already streamed is
stored in the session as the assistant's message.

## Streams & long-polling

These endpoints return **Server-Sent Events**:

- `/api/jobs/{id}/stream` — live stdout/stderr for a background job
- `/api/chat` — agent tokens + tool call events
- `/api/sync/serve` and `/api/sync/receive` — peer-sync progress events
- `/api/stream` — an `update` event when the active workspace's data changes
  (any process: ingest jobs, agents, sync). Overview and project views are
  checked against the data on every read, so refetching after an event, or
  at any time, returns current data.

Use `EventSource` in the browser, `sseclient` in Python, or `curl -N` to
consume. Postman shows raw bytes — useful for inspecting events but not for
interactive streaming.

## MCP vs HTTP

The HTTP API and the MCP server expose similar capabilities through different
transports. Pick the one that matches your integration:

| | MCP (stdio) | HTTP API |
|---|---|---|
| Consumer | Coding agents (Claude Code, Cursor, Copilot, Cline, OpenClaw) | Anything that speaks HTTP |
| Transport | JSON-RPC over stdio | REST + SSE |
| Auth | None (local process) | Local access only; no supported authenticated remote mode |
| Ingest content | [`ingest_content`](./mcp.md#writes) | `POST /api/commands/ingest*` (job queue) |
| Search | `search` | `GET /api/search` |
| Streaming | Native | SSE |
| Best for | Agent integrations | Local services, CI, dashboards |

## Browser capture (WIP branch)

The [experimental Chrome extension](browser-extension.md) uses a separate local
router. All requests require `Authorization: Bearer TOKEN` and
`X-Imprint-Extension-Id: ID`; any supplied Origin must exactly match the paired
`chrome-extension://ID`. Pairings grant one existing workspace. This router does
not expose CLI commands, arbitrary filesystem access, or general dashboard data.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/browser/status` | Paired workspace and maximum request bytes. |
| POST | `/api/browser/captures` | JSON `{project, documents:[{kind, url, title, text, account?, message_id?}]}`. Returns 202 `{job_id, status, workspace}`. Kinds: `page`, `selection`, `gmail`. Gmail requires account identity and a message ID. |
| GET | `/api/browser/jobs/{id}` | Only this pairing's capture job status, without payload or logs. |

Captures use the shared queue and inline ingestion pipeline. Request limit:
1,000,000 UTF-8 bytes; 1–50 documents; 10–800,000 characters per document.
Indexed provenance uses `source_type=browser`, `source_url` and `doc_metadata`.
See [ADR 0029](adr/0029-paired-browser-capture.md) for the boundary and WIP limits.
The downloadable extension currently sends pages and selections. Gmail support
is marked **Coming soon**; its original backend payload scaffold remains for
future development. See [ADR 0030](adr/0030-chrome-extension-release-zip.md).

## Versioning

The API follows the same release channel as the rest of Imprint — see
[installation](./installation.md#install-a-specific-version-or-channel). The
Postman collection in this repo is versioned alongside the code; the live
OpenAPI schema at `/openapi.json` always matches the running container.

## Paired sync controls

`GET /api/sync/peers` returns public pair status without credentials.
`POST /api/sync/peers/{pair_id}` accepts `{"action":"enabled","enabled":false}`
or `{"action":"forget","confirm":true}`. Forget requires prior user confirmation,
revokes every paired workspace with that device, and reports remote removal as
pending until acknowledged. Existing memories remain. The local-origin boundary
applies. Serve/receive SSE requests accept optional boolean `remember` (default
false); both sides must opt in. A `paired` event confirms completion. The backend
runs automatic reconnects while alive. See [sync](sync.md).
